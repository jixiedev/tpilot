Databot 主流水线：build_databot_graph 的状态机

一轮提问由外层状态机驱动：stage 字段决定下一个节点，五个阶段里有三个是 LLM 的 ReAct 子图、 两个是 interrupt() 人工闸门。闸门的四种裁决决定「前进 / 退回重做 / 中止」三条去路。

stage 路由表（_stage_route）

外层状态机唯一的「stage → 下一个节点」映射，VALID_STAGES 之外的值会落到 end_with_summary。
stage路由到节点这一段发生什么
fetchfetch_cardsRAG + DataHub 并行检索，LLM 用 commit_cards 选定模型卡片
gate_cardsgate_cards人工审阅卡片，可退回重选
sqlwrite_cards_artifact先落盘已通过的卡片，再起草 SQL
gate_sqlgate_sql人工审阅 SQL，可退回重写
executewrite_sql_artifact先落盘已通过的 SQL，再执行查询
doneend_with_summary终态，生成面向用户的总结

人工闸门的四种裁决

两个闸门共用同一组选项与解析逻辑（_parse_resume）；无法识别的裁决一律按 dryrun 处理。
裁决行为stage 变化
approve通过，推进到下一阶段gate_cards → sql；gate_sql → execute
deny-comments带意见退回重做，并清空本阶段产物退回 fetch / sql
deny-halt中止本轮，不执行 SQL、不写 profile→ done（end_with_refusal）
dryrun预览通过，但不写 profile artifact同 approve，另置 dryrun=True

结构

外层状态机 + 每阶段 ReAct 子图

外层只管 stage 指针；每个 LLM 阶段是一个独立子图（build_fetch_cards_subgraph / build_generate_sql_subgraph），用 state_exit_keys 判断何时退出。

人机协作

闸门是 interrupt()

闸门节点用 interrupt() 挂起等待人，四个选项各带一段 LLM 生成的说明文案；gate_decisions 记录完整审计轨迹。

副作用

只有 approve 才落盘

两张卡片 + 一条 SQL 追加写进 <profile_dir>/<user>.databot_turns.jsonl；dryrun 或无 approve 记录时直接跳过。
